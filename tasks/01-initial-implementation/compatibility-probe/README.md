# Disposable Workers compatibility probe

This is Task 00 test infrastructure, not `apps/admin` or the starter workspace. See [observed evidence and blockers](../00-compatibility.md). The GitHub repository in the config is a placeholder. No real credentials are included.

Copy this directory outside the repository before running it, so later workspace configuration cannot affect the experiment. Use Node `22.23.4` and pnpm `12.18.0` (pinned in `.nvmrc` and `package.json`). One way to invoke the exact tools without replacing the host installation is:

```sh
npm exec --yes --package=node@22.23.4 --package=pnpm@12.18.0 -- pnpm install --frozen-lockfile
npm exec --yes --package=node@22.23.4 --package=pnpm@12.18.0 -- pnpm build
npm exec --yes --package=node@22.23.4 --package=pnpm@12.18.0 -- pnpm preview --host 127.0.0.1
```

In the copied directory, check the HTTP responses and preview logs:

```sh
curl -i http://127.0.0.1:4321/
curl -i http://127.0.0.1:4321/keystatic
curl -i http://127.0.0.1:4321/api/keystatic/github/login
npm exec --yes --package=node@22.23.4 --package=pnpm@12.18.0 -- pnpm exec astro preview logs
npm exec --yes --package=node@22.23.4 --package=pnpm@12.18.0 -- pnpm exec astro preview stop
```

Without GitHub App credentials, the login endpoint returns HTTP 500 and logs missing configuration. HTTP 200 for the editor HTML does not prove browser rendering or authenticated writes.

## Node-only App provisioning

Stop the Workers dev server before starting the separate Node setup server:

```sh
npm exec --yes --package=node@22.23.4 --package=pnpm@12.18.0 -- pnpm exec astro dev stop
npm exec --yes --package=node@22.23.4 --package=pnpm@12.18.0 -- pnpm exec astro dev --config astro.setup.config.mjs --host 127.0.0.1 --port 4321
```

Visit `http://127.0.0.1:4321/keystatic/setup`, enter the isolated Worker's deployed URL, and complete GitHub App creation/installation for the test repository only. The official setup writes credentials to the ignored local `.env`. Do not copy that file into tracked source. Provision the Worker secrets separately; build/deploy with the default `astro.config.mjs`, never the setup config. This provisioning workflow does not fix or validate the Workers dev runner.
